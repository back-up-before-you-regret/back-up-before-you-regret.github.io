TL;DR
⚠️

Coding agents modify real-world state, such as software environments, databases, and files, and users often regret the loss later, when they find they still need it.

📏

RegretBench grounds 205 tasks in real-world regret moments and tests whether coding agents back up, how often, and whether it covers what humans later need.

BackUpper is a plug-in that backs up affected state before every tool call, covering every regret-moment action at $0.014 per task.

01 · Benchmark

RegretBench: built from real regret moments

Each task is built from a real-world regret moment, reported on platforms such as X.com, GitHub, and Stack Overflow, where a user explicitly reported losing state they later needed and regretted not backing it up. We pair it with a real environment and a real multi-turn conversation to build an executable task. We then measure three things: whether the agent completes the task (Pass Rate), whether it backs up before the regret moment (RMBR), and how often it backs up anything outside the workspace (OWBR). Since harnesses already snapshot the workspace, we only count backups beyond it.

02 · Method

BackUpper: check every tool call before it runs

Because it is hard to predict which changes will be regretted, BackUpper checks every tool call on the harness's pre-tool-call hook, before it runs. Read-only calls pass straight through. Common operations get a rule-based backup: rewriting the command (rm → move to trash), pairing it with a backup (pip freeze before pip install), or snapshotting workspace edits. Complex or ambiguous cases go to an LLM checker and a lightweight subagent that inspects the call and backs up what it will change. Users can customize what gets backed up in plain words, and every backup is logged with a command to restore it. We measure backup coverage (RMBR, OWBR) and how close the restored state is to the original (state similarity).

    03 · Try it

    Try it yourself: plug it into your agent

    Install BackUpper once and keep using your agent as usual. Every tool call is checked before it runs, and the state it touches is backed up first.

    Common operations are handled by rules at no model cost; complex or ambiguous cases go to a lightweight subagent. Every backup is logged with a way to restore it.

    $ npm install -g agents-backupper

# use your agent as usual
$ claude

# undo when you regret
$ backupper log
$ backupper restore <id>
